## ТЗ: Видео в практиках

### Концепция

Тренер прикрепляет видеоинструкции к активностям курса. У одной активности может быть несколько видео с разными интервалами дней. На экране таймера видео отображается над таймером, при этом таймер и видео синхронизированы: перемотка видео двигает таймер и наоборот. Длительность таймера автоматически выставляется по длительности видео (если видео есть).

### Источники видео

1. **Загрузка файла** — видео сохраняется в Supabase Storage (bucket `course-videos`)
2. **Ссылка YouTube** — встраивается через iframe (YouTube Player API для синхронизации)
3. **Ссылка Google Drive** — встраивается через iframe `/preview` (без синхронизации — ограничение API)
4. **Прямая ссылка** — воспроизводится через HTML5 `<video>` (с синхронизацией)

### Модель данных

```
activity_videos
├── id              UUID PK
├── course_id       UUID FK → courses
├── activity_id     TEXT           -- ID активности в course_activities
├── video_type      TEXT           -- 'file' | 'youtube' | 'drive' | 'link'
├── video_url       TEXT           -- URL в Storage, YouTube, Drive или прямая ссылка
├── file_size       BIGINT         -- размер файла в байтах (для file)
├── duration_sec    INT            -- длительность видео в секундах
├── first_day       INT DEFAULT 1  -- с какого дня показывать
├── last_day        INT DEFAULT 1  -- по какой день (по умолчанию = только 1 день)
├── sort_order      INT DEFAULT 0  -- приоритет при пересечении интервалов
├── created_at      TIMESTAMPTZ
└── UNIQUE(course_id, activity_id, first_day, last_day)
```

### Логика выбора видео для дня

Для активности A в день D:
1. Найти все записи `activity_videos` где `activity_id = A` и `D >= first_day` и `D <= last_day`
2. Если найдено несколько — взять с наибольшим `sort_order` (последнее добавленное)
3. Если не найдено — таймер работает без видео, по своему `duration_min`

### Пример

Курс 20 дней, активность "Разминка":

| Видео | first_day | last_day | Результат |
|-------|-----------|----------|-----------|
| Видео 1 | 1 | 6 | Дни 1-6: Видео 1 |
| Видео 2 | 7 | 9 | Дни 7-9: Видео 2 |
| Видео 1 | 10 | 20 | Дни 10-20: Видео 1 |

Одно и то же видео можно привязать к нескольким интервалам.

#### Синхронизация видео ↔ таймер

- При наличии видео: `duration_min` таймера = длительность видео (из `duration_sec`)
- Drag по кругу таймера → `video.currentTime = новое_время`
- Seek видео (клик по прогресс-бару) → обновить `elapsed` таймера
- Play/Pause таймера → play/pause видео
- Завершение видео → завершение таймера → отметка `completed`
- Если видео нет для этого дня — таймер работает как раньше, по `duration_min`

#### YouTube: синхронизация через YouTube IFrame Player API
- `player.seekTo(seconds)` при drag таймера
- `player.getCurrentTime()` для обновления таймера при seek видео
- События `onStateChange` для play/pause синхронизации

### Хранение видео (Supabase Storage)

- Bucket: `course-videos` (private, доступ через RLS)
- Путь: `{course_id}/{activity_id}/{filename}`
- Лимит размера файла: 500 МБ (настраивается в Storage политиках)
- Допустимые форматы: mp4, webm, mov
- Подписанные URL для доступа учеников (signed URL, TTL = 1 час)

## ТЗ: Типы практик

### Концепция

Практики бывают разных типов. Тип определяет layout экрана таймера и доступные варианты контента. Тренер выбирает тип практики в конструкторе курса из выпадающего списка. Для каждого типа доступны свои виды загружаемого контента.

### Типы и их layout на экране таймера

#### 1. Практика с медиа (тип `media`) — по умолчанию

Универсальная практика. Layout адаптируется в зависимости от загруженного контента:

**Контент не добавлен** → только таймер, без заглушки:
```
┌─────────────────────────────┐
│  ←  Разминка                │
│                             │
│        ┌──────────┐         │
│       /   15:30    \        │
│      │   круговой   │       │
│       \   таймер   /        │
│        └──────────┘         │
│                             │
│      [Пауза]  [Готово]      │
└─────────────────────────────┘
```

**Только текст** → таймер сверху, текст снизу (с прокруткой):
```
┌─────────────────────────────┐
│  ←  Разминка                │
│        ┌──────────┐         │
│       /   15:30    \        │
│      │    таймер    │       │
│       \            /        │
│        └──────────┘         │
│ ┌─────────────────────────┐ │
│ │ Текстовое описание      │ │
│ │ практики с прокруткой   │ │
│ │ и форматированием...    │ │
│ └─────────────────────────┘ │
│      [Пауза]  [Готово]      │
└─────────────────────────────┘
```

**Видео** → видео сверху, текст (если есть) с прокруткой и кнопкой развернуть, таймер внизу:
```
┌─────────────────────────────┐
│  ←  Разминка            ⛶   │
│ ┌─────────────────────────┐ │
│ │       VIDEO PLAYER      │ │
│ │   (синхронизация с      │ │
│ │    таймером)            │ │
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │ Текст (сворачиваемый)   │ │
│ │              [Развернуть]│ │
│ └─────────────────────────┘ │
│        ┌──────────┐         │
│       /   таймер   \        │
│        └──────────┘         │
│      [Пауза]  [Готово]      │
└─────────────────────────────┘
```

**Картинка** → картинка сверху, текст (если есть) под ней, таймер внизу:
```
┌─────────────────────────────┐
│  ←  Разминка                │
│ ┌─────────────────────────┐ │
│ │      ИЗОБРАЖЕНИЕ        │ │
│ │  (масштабируемое, tap   │ │
│ │   для просмотра)        │ │
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │ Текст (если есть)       │ │
│ └─────────────────────────┘ │
│        ┌──────────┐         │
│       /   таймер   \        │
│        └──────────┘         │
│      [Пауза]  [Готово]      │
```

## ТЗ: Онлайн с мастером

### Концепция

Тренер назначает видеозвонок на определённый день и время. Ученики видят это как практику и в назначенное время заходят в звонок. После завершения звонка автоматически появляется видеозапись. Реализация через сервис **Daily.co** (iframe embedding).

### Логика работы

#### До звонка
- Тренер в конструкторе назначает день и время звонка
- За **2 часа** до звонка всем ученикам отправляется push-уведомление
- Практика отображается как "Ожидание звонка" с обратным отсчётом
- За 5 минут до начала кнопка "Войти" становится активной

#### Во время звонка
- Ученики нажимают "Войти" → открывается iframe Daily.co
- Тренер (owner) управляет звонком: может mute/kick участников
- Ведётся автоматическая запись (Daily.co cloud recording)
- Трекинг присутствия: фиксируется время join/leave каждого участника

#### После звонка
- Тренер завершает звонок
- Запись обрабатывается Daily.co (обычно 5–15 минут)
- Webhook от Daily.co → сохраняем URL записи в `activity_videos`
- Запись автоматически появляется как видео для этой практики
- Ученики, пропустившие звонок, могут посмотреть запись

### Правила завершения

Практика "Онлайн с мастером" считается завершённой если выполняется **любое** из условий:

1. **Полное присутствие** — ученик был на звонке ≥80% времени (автоматически)
2. **Отметка мастера** — тренер вручную отметил ученика как "присутствовал"
3. **Просмотр записи** — ученик посмотрел полную запись звонка (таймер дошёл до конца, как обычное видео)

Можно завершить **в любой день**, не только в текущий.

## ТЗ: Карта курса и Статистика

### Концепция

На главном экране (Dashboard) под именем курса появляются **две кнопки**: «Карта курса» и «Статистика». Они дают ученику обзор всего курса и текущий прогресс, не дожидаясь завершения.

### UI: Расположение кнопок

Кнопки располагаются сразу под строкой с названием курса, перед блоком "Прогресс":

```

│ ┌───────────────┐ ┌───────────────┐ │
│ │ 🗺 Карта курса │ │ 📊 Статистика │ │
│ └───────────────┘ └───────────────┘ │
│                                     │
│ Прогресс                  3/30      │
│ ○─○─○─●─○─○─○─○─○─...              │
│                                     │
│ День 4 ...                          │
└─────────────────────────────────────┘
```

Стиль кнопок: glassmorphism, одинаковой ширины (flex: 1), gap: 8px. Неактивная — с лёгкой обводкой, при нажатии — фон подсвечивается.

### Экран «Статистика»

Открывается поверх дневного контента (заменяет блок "День X" и карточки практик, аналогично тому, как `CourseCompleteView` заменяет обычный контент при завершённом курсе).

**Отличия от финального экрана завершения:**
- Вместо блока "Поздравляем! Курс окончен" показывается текущий день:
  ```
  ┌─────────────────────────────────────┐
  │         📊                          │
  │    Текущий прогресс                 │
  │    День 12 из 30                    │
  └─────────────────────────────────────┘
  ```
- **Цвет шкал всегда зелёный** — кольцевая диаграмма и все прогресс-бары активностей используют зелёный (`#27ae60` → `#2ecc71`) независимо от процента выполнения. Никаких оранжевых/красных цветов.
- Остальная структура идентична `CourseCompleteView`:
  - Кольцевая диаграмма с процентом (всегда зелёная)
  - Дней выполнено: X из Y
  - Общее время: X ч Y мин
  - Длительность: Z дней
  - Результаты по активностям — иконка, название, процент, прогресс-бар (зелёный), "X из Y занятий"
- Кнопка «Назад» (←) или повторное нажатие «Статистика» возвращает к обычному виду дня

**Изменение для финального экрана (CourseCompleteView):**
- Цвет шкал тоже меняется на **всегда зелёный** — убрать условную логику `pct >= 80 ? GREEN : pct >= 50 ? orange : red`. Всегда зелёный градиент.

- **Номер дня** — "День 1", "День 2" и т.д.

- **Прогресс-бар** — зелёный заполненный по проценту завершённых практик
- **Стрелка ▼** (справа внизу) — раскрывает список практик дня

## ТЗ: Безопасность регистрации

### Статус: регистрация по email/паролю временно отключена

До реализации нижеперечисленных мер регистрация новых пользователей через email/пароль возвращает 403. Вход для существующих пользователей работает. Google OAuth создаёт аккаунты (после настройки домена).

### Необходимые меры

1. **Email confirmation**
   - [ ] При регистрации отправлять письмо со ссылкой подтверждения
   - [ ] Поле `email_verified` в таблице `users` (BOOLEAN DEFAULT FALSE)
   - [ ] Запрет входа до подтверждения email
   - [ ] Resend ссылки подтверждения (cooldown 60 сек)
   - [ ] Сервис отправки писем (Nodemailer + SMTP или Resend/SendGrid)

2. **Captcha**
   - [ ] Интеграция reCAPTCHA v3 или hCaptcha на форму регистрации
   - [ ] Серверная валидация токена captcha
   - [ ] Captcha также на форму входа (после 3 неудачных попыток)

3. **Rate limiting**
   - [ ] Ограничение попыток входа: 5 за 15 мин на IP
   - [ ] Ограничение регистраций: 3 за час на IP
   - [ ] Ограничение запросов API: 100/мин на пользователя
   - [ ] Библиотека: `express-rate-limit`

4. **Валидация пароля**
   - [ ] Минимум 8 символов
   - [ ] Хотя бы одна цифра и одна буква
   - [ ] Проверка на утечённые пароли (Have I Been Pwned API — опционально)

5. **Защита от abuse**
   - [ ] Блокировка одноразовых email-доменов (disposable email)
   - [ ] Логирование попыток входа (IP, user agent, timestamp)
   - [ ] Уведомление пользователя о входе с нового устройства

### Порядок включения регистрации

1. Реализовать email confirmation + captcha + rate limiting (минимум)
2. Протестировать на staging
3. Убрать `return res.status(403)` из `backend/routes/auth.js`
4. Задеплоить
